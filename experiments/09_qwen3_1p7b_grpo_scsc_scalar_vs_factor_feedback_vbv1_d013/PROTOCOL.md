# Protocol: isolate reward partial credit and factor disclosure during Lean policy training

**Doc link:** <https://github.com/brando90/rl-4-code-verification/blob/main/experiments/09_qwen3_1p7b_grpo_scsc_scalar_vs_factor_feedback_vbv1_d013/PROTOCOL.md>

**TLDR:** Design frozen before new main-training outcomes. Execution identities, resource reservation and the throughput-selected horizon must be locked in a separate execution manifest before the first admitted optimizer update. Technical preflight may diagnose implementation; it never chooses an arm, checkpoint or horizon based on favorable outcomes.

## Scientific question (locked)

B minus A estimates the effect of replacing the exact three-factor conjunction by its geometric mean. C minus B estimates the effect of explicit factor disclosure with the same smooth reward. Both use Group Relative Policy Optimization (GRPO), the same initialization, generated-token limits, prompt order, sampling, verifier, judge and fixed two-turn interaction. This does not test CoDaPO simultaneously.

## Initialization, splits and seeds

Initialization: experiment08's Qwen3 Base 1.7B full-schedule step-658 export, with every file hash and tokenizer/chat-template revision verified. Selection is by completed training schedule, independent of validation results. Inherit D-013's exact 539 / 135 / 222 manifest and contamination screens. Use paired seeds 20261008 and 20261009. The training pool is all 539 train tasks; each seed uses a fixed shuffled cyclic schedule without score-based filtering or resampling. Publish the actual sampled task sequence and coverage. Four prompt groups per update and eight samples per group. No task sampling based on observed success.

## Reward and feedback

For an extracted, compile-valid, nonvacuous response let the three frozen scorer factors be t, p, f (IC_tests, IC_proofs, FSC). S = (t*p*f)^(1/3). Use the existing gated implementation in `src/rl4cv/rewards.py`; never loosen the proof kernel, axiom allowance or reference material. The harsh target H is exactly 1[t=1 and p=1 and f=1], with the same gates. No epsilon or post-hoc coverage threshold. Also report the separate existing `kernel_binary` diagnostic; do not call it H or a complete semantic correctness test.

A receives terminal reward H; B and C receive terminal reward S. Every arm receives the same first-turn S, H, and capped compiler text. C alone additionally receives the explicitly named t, p, f values. No judge rationales, gold text or extra repair instructions are disclosed. Feedback serialization, precision and message boundaries are fixed and hashed. Missing required FSC is null and blocks the optimizer batch; it is never converted to zero or silently dropped. When the frozen gate mathematically forces S and H to zero, an unrequested judge is marked not-required, not measured zero. All arms perform the same eligibility checks and judge procedure, even A.

Two assistant turns per rollout; reward is zero after the first turn and the chosen terminal reward after the second. Score the last assistant file, not concatenated files. Train on assistant tokens only, never environment feedback or prompt tokens. Verify raw environment-token handling against the runtime's Qwen chat template: proper user feedback and assistant generation boundaries must be delivered exactly. The completion reminder from agents-config is frozen into every initial and continuation prompt with only inapplicable tool/file instructions adapted; no outcome-dependent extra turns.

## Judge and source identity

FSC uses the validated `vb103_judge` Valkyrie agent under D-102, unchanged prompts, rubric, GPT-6 Sol high and Claude Opus 5.5 max, three ratings each, per-model medians then their mean divided by five. Verify the saved route's actual organization, managed credential source, payer and positive/negative controls before use. All measured closed-model calls are Vals-funded; no personal subscription fallback and no host-authored provider calls. Cache only byte-identical response/reference/judge-config inputs; record all six underlying ratings and charges. Preserve native missing/error status. Self-hosted open-weight generation is authorized under D-101. Scientific configuration cannot fall back silently.

Pin the actual installed trainer, generation engine, library versions, policy initial weights, template, scorer, judge bundle and this repository source. D-105's historical paper-code pin is provisional; this is a newly specified experiment, not a claim of reproducing that paper's submitted settings.

## Preflight and admission

1. Technical controls prove two-turn boundaries, terminal-only reward, loss masks, final-response extraction, proof/vacuity gates, unknown-FSC handling, cache identity, optimizer/rollout weight synchronization, save/reload and resource enforcement. Run actual deterministic scorer controls and one bounded optimizer plumbing step on a separate private disposable checkpoint. Never use that checkpoint as an arm initialization.
2. On the first 32 train tasks under the first seed's fixed schedule, generate eight two-turn samples each using the unchanged initialization and scalar-feedback contract. This is a declared 256-rollout calibration set, not held-out evidence. Score every cell. Require at least one positive within-group S variance and at least one S unequal to H. These are minimal informativeness conditions, agent-chosen before calibration, not claims of adequate statistical power. If they fail, publish a terminal uninformative-reward gate; do not train indistinguishable arms or add sampled tasks until it passes.
3. Use only measured runtime/memory/length/throughput from that calibration and the technical step to select the largest horizon in {32,16,8} updates predicted conservatively to fit all six trajectories plus evaluation and cleanup inside the fixed allocation. The outcome scores never determine this choice. If even eight updates cannot fit, report capacity blocked. Freeze the chosen horizon, scheduling order, all optimizer settings and manifests before main training. Record extrapolation method and uncertainty; leave enough end-stage reserve. Do not claim the upper-bound plan fits merely because a smoke test ran.
4. Existing experiment08's readiness gate has not passed for the inspected partial ladder. This new study is explicitly exploratory and uses its own technical/informativeness gate; never edit or retroactively pass the earlier gate. No test outcomes are read before all six endpoint hashes are frozen.

## Main training and execution bounds

Exactly three arms times two paired seeds: six trajectories, each starting from identical initial weights, with the same horizon and task schedule for a given seed. Alternate arms across seeds by a precommitted balanced order. No outcome-dependent stopping or checkpoint selection. Save durable intermediate checkpoints for infrastructure resume only; the endpoint is the fixed horizon.

Maximum per assistant turn 8,192 new tokens, exactly two turns; preflight verifies the context window can hold the largest frozen prompt, both turns and feedback (minimum 24,576 token context unless the actual tokenizer-bound context requires more). Use temperature 0.6, top-p 0.95, top-k 20. Overlong-response handling, GRPO advantage normalization, optimizer learning rate/clipping/KL settings and update minibatches must be recorded exactly in the execution freeze; no unverified default may become a hidden scientific condition. Prefer the verified runtime contract and record deviations from any historical paper settings. B and C must be identical except feedback content.

At the maximum 32-update horizon there are 6*32*4*8 = 6,144 main-training rollouts and 12,288 assistant responses. Calibration adds 256 rollouts/512 responses. Validation and test declarations are below. Every eligible response has one logical six-rating judge invocation under the validated judge's fixed internal retry policy; no outcome-triggered replacement or extra rating. The compiler and judged-response caches preserve exact provenance. No external solver/teacher generation is admitted.

Maximum additional allocation: two otherwise-idle A100 devices, 32 A100 device-hours and 16 elapsed hours from admitted remote setup, including calibration, training, evaluation and cleanup. Zero paid cloud hardware, no new credits/charges or administrator budget changes. At most eight concurrent local scorer workers, with a task-owned bounded queue; no bulk parallel builds. Keep at least 5% disk headroom and cap new owned data at 200 GiB; preserve other owners' files. Resource estimates are unknown until actual preflight; record them before GPU admission. Set CUDA_VISIBLE_DEVICES explicitly. Do not share with another user's resident GPU process. Coordinate with experiment08's live owner before claiming devices; use shared lease/admission evidence and preserve existing healthy jobs. Release devices during long judge waits when the runtime can resume safely; otherwise bound/record idle reservations. No laptop training.

At deadline do bounded teardown/checkpointing and report every missing trajectory/cell. One identical infrastructure restart per interrupted unit is admitted only when its optimizer/RNG/data-position state can be restored exactly; otherwise retain the interrupted condition, no fresh seed or best-of splice. A watchdog may restart an executor without duplicating healthy training.

## Held-out evaluation and aligned matrices

One common one-turn, no-feedback harness evaluates the unchanged initialization and six fixed endpoints, one sample per task per checkpoint using a fixed evaluation seed and the same 8,192-token cap. Validation: all 135 tasks for all seven policies (945 cells). Test: all 222 tasks for all seven policies (1,554 cells), after every endpoint hash is locked; no test-based repair, hyperparameter change or checkpoint choice. Reuse existing identical cells only if checkpoint, prompt, tokenizer, seed, sampler, cap and scorer/judge hashes all match; otherwise this protocol's declared evaluation is distinct. Keep test material isolated from the training owner until endpoint freeze.

For every item preserve task ID, split, arm, seed, checkpoint, extraction/compilation, t/p/f, per-file S, H, kernel_binary, truncation, token/call costs, errors and exact measurement status. A display aligns factor columns directly beside H, keeping nulls distinct from failures. Before/after tables show changed factors, score, target transitions and regressions. Never select only changed/successful examples. Official aggregate SCSC is the geometric mean of factor means on a common measured cohort; average per-file S is a separate diagnostic.

Primary comparisons: paired C-B and B-A held-out H-rate differences, plus each endpoint versus the fixed initialization. Report both seeds individually, pooled paired task effects with 95% task-cluster bootstrap intervals, seed count and seed spread; p-val=n/a unless a test was frozen before outcomes. With only two seeds do not claim broad training-seed generalization. Report FSC, proof, compilation and truncation changes, full-denominator completion, common-cohort sizes and worst-case missing-outcome bounds. A positive mean alone is exploratory; evidence of an improvement requires positive paired effect with its interval excluding zero and no hidden missingness/reward-hacking explanation. A nonpositive result, ceiling, zero-advantage baseline or failed gate is published equally.
