# Experiment 13 v2-S2 durable anchor scoring

**Doc link:** <https://github.com/brando90/rl-4-code-verification/blob/main/experiments/13_irt_scsc_factor_guided_vs_direct_pass1_rl_sft_qwen3_vbv1_d013/expt_v2/phase1/SCORING_S2_LEDGER.md>

**TLDR:** `score_anchor_ledger.py` adds durable cell-level supervision around the unchanged `score_anchor.py` worker. It never regenerates a response or changes extraction, the official strict oracle, partial components or resource limits. Every completed score survives restart; a missing/transient measurement receives at most one identical infrastructure retry under the existing L1 rule.

No new anchor score has run at this implementation's preparation. Each full batch must close and publish its complete generation report before a separate `ANCHOR_SCORE_S2` lock binds every available response, manifest, allowlist, scorer dependency and the S2 admission. The driver verifies the published revision and every hash before reading data. Independent full batch 2 also binds the published calibration/F2 receipt. All 4,312 slots receive a final private record, including missing generations, exhausted retries and integrity defects.

The worker remains unchanged: original frozen extraction, independent strict scorer and elaborator probe; 64 GiB per-worker address-space cap; 3,600-second supervisor cap. One scoring controller runs at a time under a process-held file lock. At most 48 concurrent workers are admitted, further limited by half currently available memory divided by the frozen 6.928 GB 99th-percentile working set; admission waits below 25% available system memory. Central-processor scoring makes no graphics-processor claim or model call.

Before launching, a cell records the source hash, scoring-lock hash, exact identity, numbered attempt and unique cleanup marker. A resumed controller first cleans only that attempt's marked processes using the existing process-identifier-file-descriptor cleanup. A saved worker receipt is recovered without rescoring, including a crash between cleanup and receipt persistence. Missing worker receipts and the explicitly listed transient operating-system/connection errors allow attempt 2 only after cleanup is verified. Deterministic limits, other measurement errors and unresolved cleanup are final unmeasured outcomes; they never trigger a third attempt or a replacement generation.

Completed cells are never recomputed. Their identity and scoring-lock hash must match on resume. All attempt logs remain private. A final ordered ledger and hash accompany measured/declared counts, strict full-denominator bounds, capped-response counts, retry counts and integrity/cleanup counts. Unmeasured cells are never assigned strict zero. Unresolved integrity or cleanup defects prevent calibration admission. A missing outcome after the allowed recovery remains in the full denominator and later forecast bounds.

The synthetic regression tests cover measured-cell reuse, identical bounded retries, deterministic-limit exclusion, cleanup failure, worker-receipt recovery, lost-controller recovery and input-identity defects. The existing required Lean test still executes the original worker on a valid capped response and verifies strict success is retained. This changes process persistence, not the scientific scorer.
