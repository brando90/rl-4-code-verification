# Experiment 13 v2-S2 evaluation contract preparation

**Doc link:** <https://github.com/brando90/rl-4-code-verification/blob/main/experiments/13_irt_scsc_factor_guided_vs_direct_pass1_rl_sft_qwen3_vbv1_d013/expt_v2/phase2/EVALUATION_S2_METHOD.md>

**TLDR:** Preserve PROTOCOL section 7’s exact historical ladder sampling/template for validation and selected-test evaluation. This preparation is not an execution lock or permission to unseal test content. The pilot and main locks must bind the implementation, source evidence and complete evaluation manifests before execution.

The historical source is experiment 08’s `expt_v1/scripts/run_ladder_e08.sh`, using `src/rl4cv/veribench/generate.py`. Evaluation uses temperature 0.6, top-p 0.95, top-k 20, a 12,288-new-token cap, thinking on, the unchanged `build_prompt(addendum='vbv1')` messages, and `apply_chat_template(tokenize=False, add_generation_prompt=True, enable_thinking=True)`. The extra stop token is `<|im_end|>`; model end-of-sequence handling and SamplingParams defaults remain as in that generator. Each sample’s seed is `91*100003 + sample_idx`, shared across tasks. Preserve the engine’s returned output text, including its default special-token handling, when using the frozen extraction/scoring path. Do not substitute training’s 8,192-token unconstrained sampler or its explicit token decoding.

PROTOCOL specifies all 135 validation tasks × 8 samples at each of four common cumulative-token checkpoints, and all 222 test tasks × 16 samples at the one selected checkpoint per arm/seed. Main seeds remain 13011, 13012 and 13013. The same evaluation randomness applies across arms and checkpoints. The S2 numerical dtype is float16. Engine batching, context length, memory utilization, device ownership, runtime versions and complete export/tokenizer hashes must be separately bound in the execution lock; the historical sampler does not imply byte-identical runtimes or outputs. The installed full-SFT model’s configuration has a 32,768-token context. Evaluation cost measurement must use the 12,288-token cap.

`evaluation_contract.py` reuses the historical prompt builder and exact SamplingParams arguments. Its authored sampler test compares arguments with the actual historical engine wrapper; its prompt test verifies the frozen addendum hash and delivered template options. The identity builder requires full task counts, fixed main seeds and all declared samples. It reads no task content itself. Unknown strict outcomes stay unknown, with the declared denominator and sharp binary mean bounds retained. Token-cap metadata never forces strict failure.

Checkpoint selection maximizes full-validation strict mean, with ties going to the later token boundary. With incomplete receipts, select a checkpoint only if this same maximizer is identified under every completion of the missing binary outcomes; an unresolved ordering stays INCONCLUSIVE. This is a conservative implementation of the unchanged maximum-and-tie rule, chosen before any evaluation outcome. It neither substitutes an observed subset nor reruns a completed cell. Selection alone does not admit test access: the selected export, all four validation inventories, analysis choices, resource envelope and test manifest still need their published execution freeze.

No new validation/test generation, baseline factor inspection, checkpoint selection or test scoring has run. Existing baseline receipts may be reused only after verifying compatibility; historical bfloat16 receipts are not assumed compatible with v2-S2 float16. No test baseline factor or new test output may define analysis strata before the analysis freeze.
