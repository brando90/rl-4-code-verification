## Deviations

1. **Grading Lean project.** Experiment 103's candidate at `veribench_vb103/veribench_dataset/lean_src` (read-only) was not built (empty `.lake`, "no previous manifest"); never ran `lake build`/`cache` there (left it untouched, confirmed clean `git status`). Built a fresh grading project instead at this repo's own `external/veribench_scorer/veribench_dataset/lean_src` via `lake exe cache get` (never `lake build` of Mathlib). `lake env lean` exits 0 on a gold file. No change to scoring semantics.
2. **CUDA toolchain.** The pip-installed vLLM 0.30.0 / torch 2.13.0+cu130 wheels need `nvcc` flags (`--compress-mode=size`) that the host's default `nvcc` (CUDA 12.4) doesn't support, crashing flashinfer's JIT sampling kernel on first engine init. Fixed by prepending `/usr/local/cuda-12.8/bin` (present on the host) to `PATH` in the venv's `activate` script. No effect on sampling semantics (flashinfer's top-k/top-p kernel compiles and runs normally under 12.8); purely a build-toolchain fix.
3. **Qwen3.6-27B route control needs `tp=2`.** Flagged as a possibility in `DISPATCH_e01.md`. At `tp=1`, `gpu_memory_utilization=0.88` on an 80 GB A100, vLLM's KV-cache sizing failed: "16.32 GiB KV cache is needed, which is larger than the available KV cache memory (15.44 GiB)" after ~54 GB of bf16 weights. Relaunching with `tp=2`, paired with a second free GPU from {4, 5, 6} (never 0-2, which belong to another user) once one frees up. No change to sampling settings; `tp` is an inference-engine parallelism choice, not part of the locked protocol's sampling parameters.
4. **Probe subset size.** `python -m rl4cv.veribench.pack --per-split 4` produced 128 tasks, not the "at most 132" in PROTOCOL.md — only 32 splits are present with ≥4 tasks in the 896-task pack (897/32≈28 tasks/split on average; PROTOCOL.md's "4 per split, at most 132" already anticipates a split could yield fewer than 4, hence "at most"). Recorded for the record; not a deviation from the locked rule, just the observed count.
5. **Scorer control task choice.** First attempt at the hand-built scorer controls (cc.md §4) used 4 arbitrary tasks from the probe subset. One of them — `aerospace_set_real__my_fprime_crc_payload_size` — legitimately scored IC_proofs=0.667 on its *unmodified* pack gold, not 1.0, because the pack's own gold file uses `native_decide` inside a named theorem (`witness_thm`), which taints its kernel axioms (and those of the dependent `correctness_thm`) under this project's "never loosened" rule (axioms must be within `{propext, Classical.choice, Quot.sound}`). This is a genuine property of that task's gold reference, not a scorer bug. Switched the "must be 1/1" controls to `easy_set__1_myadd` and `cs_set__binary_search`, already validated clean in the 09-30-2026 CPU pilot. All 4 controls now pass exactly as PROTOCOL.md/cc.md specify.
6. **Web search for newer small Qwen releases (09-30-2026).** Found Qwen3.8 Omni Flash (released 09-23-2026) and Qwen3.8-27B / Qwen3.5-27B multimodal checkpoints (09-02-2026), newer than the `models.yaml`-declared Qwen3.5 (03-02-2026) lineup. **Not added** — per cc.md, "a new model is a new condition," never a silent edit to the locked `models.yaml`. Would need a new `expt_v2` to include them.
7. **Extraction bundle.** Diffed the committed `single_call.py` (`c7cbe3e6…`) against experiment 103's pushed bundle (`6e1a9b0d…`): the committed version adds VBV2 multi-file path-policy code (`PATH_POLICIES`, `root`, `max_files`) that is inert under `--addendum vbv1` (`root=None`, `max_files=1`). `extract_files`/`resolve_paths` behave identically to the pushed bundle for this experiment's VBV1 condition. Extraction logic identical: **yes** (for vbv1).
